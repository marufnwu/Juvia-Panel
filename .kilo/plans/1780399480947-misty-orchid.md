# Plan: Fresh Install & Full Verification of Juvia Panel

## Current State Assessment

The server at `192.168.0.211` has a broken Juvia Panel installation with multiple issues:

1. **WebSocket CORS blocking** — Logs show `websocket: request origin not allowed by Upgrader.CheckOrigin` (the HTTP CORS was fixed but WebSocket CORS in `hub.go` has the same bug)
2. **Agent service crashing** — `status=226/NAMESPACE` (ProtectSystem=strict too restrictive)
3. **Login returns 401** — needs investigation after WebSocket fix
4. **User wants a clean fresh install** to verify everything works

## Root Causes

### 1. WebSocket CORS (backend/internal/websocket/hub.go:92-113)
The `CheckOrigin` function has the same issue as the HTTP CORS had: when both `AllowedOrigins` and `PanelDomain` are empty, it returns `false` instead of allowing the request.

Current code:
```go
if cfg.AllowedOrigins == "" {
    return cfg.PanelDomain != "" && strings.Contains(origin, cfg.PanelDomain)
}
```

### 2. Agent Service NAMESPACE Error
The installed service on the server uses `ProtectSystem=strict` but the agent needs to read `/etc/panel/config.yml` which is blocked by strict mode.

## Plan

### Step 1: Fix WebSocket CORS in hub.go
- Update `CheckOrigin` to allow all origins when both `AllowedOrigins` and `PanelDomain` are empty (same logic as the HTTP CORS fix)
- Also allow localhost/127.0.0.1 always

### Step 2: Fix Agent Service
- Update `backend/config/panel-agent.service` to remove `ProtectSystem=strict` or change to `full`
- Add `/etc/panel` to `ReadWritePaths` (or remove the strict protection)

### Step 3: Uninstall current broken install on server
- Run `juvia-uninstall --purge` on the server to clean everything
- Verify all services stopped, files removed, user removed

### Step 4: Reinstall fresh
- Run install script: `curl -sf https://raw.githubusercontent.com/marufnwu/Juvia-Panel/master/scripts/install.sh | sudo bash`
- OR clone repo, build locally, and deploy manually

### Step 5: Verify end-to-end
- Check all services running (juvia-api, juvia-caddy, juvia-agent)
- Test API health: `curl http://localhost:2053/health`
- Test login from browser at `http://192.168.0.211:2053`
- Verify WebSocket connects
- Test registration flow (if no users exist)
- Test login flow

### Step 6: Verify CORS is working
- Make a cross-origin request to login endpoint
- Check response has `Access-Control-Allow-Origin` header
- Verify WebSocket upgrade succeeds
